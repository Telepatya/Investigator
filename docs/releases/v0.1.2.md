# Investigator v0.1.2 — Windows installation fix

Investigator v0.1.2 fixes first-run dependency installation from the Windows
release archive. It supersedes v0.1.1 for new installations.

## Fixed

Fresh Python 3.11 virtual environments include pip 23.2.1. After v0.1.1 was
published, a newer `google-auth` release began satisfying a transitive
`google-auth[requests]` range. During hashed installation, the older pip resolver
attempted to use that unpinned newer release even though the compiled lock pinned
`google-auth==2.55.1`, causing the launcher to stop before startup.

The launcher now installs the complete uv-compiled lock with
`--require-hashes --no-deps`. This means only the exact named versions and hashes
in the lock can be installed; pip cannot re-resolve package metadata to a newly
published version. The launcher then runs `pip check` to verify that the installed
closure satisfies all package metadata.

CI and the release workflow use the same installation mode. The fix was
reproduced with a clean Windows CPython 3.11 virtual environment using pip 23.2.1,
and the locked FastAPI, Google Auth/GenAI, MemProcFS, and YARA imports succeeded.

## Install and upgrade

Install 64-bit CPython 3.11 or 3.12, verify the release checksums, extract the
ZIP to a user-writable directory, and run `run.bat` or `python run.py`. Node.js is
not required by the release archive.

No case-database migration is introduced. Existing v0.1.1 users whose dependency
installation completed may upgrade normally. Users affected by the v0.1.1
first-run error can use the temporary workaround below or download v0.1.2.

```cmd
set PIP_NO_DEPS=1
python run.py
set PIP_NO_DEPS=
```

The first successful run records the lock digest, so the workaround is needed
only for the failed v0.1.1 installation.
