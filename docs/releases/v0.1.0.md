# Investigator v0.1.0 — public beta

Investigator v0.1.0 is the first public beta. It is intended for local,
analyst-assisted evaluation; deterministic and AI-generated conclusions must be
confirmed against the underlying evidence.

> **Historical source tag:** `v0.1.0` was pushed as an unsigned annotated tag,
> and no GitHub Release was published for it. It must not be moved or presented
> as an official signed binary release. The first artifact-bearing release target
> is `v0.1.1`.

## Highlights

- Ingests EVTX, JSON/JSONL/CSV, Defender and Sentinel exports, Linux and web
  logs, collector ZIPs, and generic forensic artifact rows.
- Correlates normalized events into timelines, process/entity relationships,
  deterministic findings, ATT&CK coverage, and analyst-controlled findings.
- Optionally analyzes raw memory through MemProcFS and YARA.
- Offers local Ollama or explicitly configured remote AI providers for reports
  and evidence-grounded chat.

## Install on Windows

1. Install 64-bit CPython 3.11 or 3.12 and ensure `python` is on `PATH`.
2. Verify `SHA256SUMS.txt` as described in `docs/RELEASING.md`.
3. Extract the ZIP to a user-writable local directory.
4. Run `run.bat`. The first launch creates `backend/.venv` and installs the
   hashed Python dependency lock; the frontend is already built.
5. Open `http://localhost:8400` if the browser does not open automatically.

Node.js is not required for the release archive. It is required when building
the frontend from a source checkout.

## Support and dependencies

Windows 11 x86-64 is the packaged and release-validated target. Ubuntu 24.04
x86-64 supports the core source workflow. Other environments are community best
effort. CPython and the locked core runtime are required. MemProcFS, YARA, custom
YARA rules, and every AI service are optional capabilities.

See [../SUPPORT.md](../SUPPORT.md) for the authoritative OS, toolchain, required,
and optional dependency matrix.

## Migration

This is a pre-1.0 case schema. Stop Investigator and copy the complete
`~/.investigator/` directory before upgrading. Databases migrate forward on
open; downgrade is unsupported. Parser corrections are not retroactive and
require evidence re-ingestion. See [../MIGRATIONS.md](../MIGRATIONS.md).

## Demonstration case

Import `demo/synthetic-case/synthetic-defender.jsonl` into a new case. It creates
nine synthetic events across filesystem, process, persistence, network, and
account categories. All identities, domains, networks, timestamps, and hashes
are generated examples.

## Known limitations

- Single-user, loopback-only, and unauthenticated; not a network service.
- The Windows distribution is a ZIP, not an MSI, and requires Python.
- Memory analysis is optional and platform/profile dependent.
- Jobs do not resume after process restart.
- Parsers, detections, YARA, and AI assistance may miss activity or produce
  false positives; evidence validation remains the analyst's responsibility.
- Case databases cannot be downgraded after a migration.

The maintained list is [../KNOWN_LIMITATIONS.md](../KNOWN_LIMITATIONS.md).
