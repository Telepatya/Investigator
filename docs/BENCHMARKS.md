# Benchmarks

Investigator's benchmark suite (ROADMAP.md workstream 1) makes performance
measurable and repeatable: one command runs the whole local suite over
deterministic synthetic corpora, emits machine-readable JSON, and a compare
command turns two result files into a regression report.

Benchmarks use **synthetic, redistributable corpora only** — never real case
material — and never contact a remote AI provider. Runs are isolated in a
temporary directory and never touch `~/.investigator`.

## Running the suite

From `backend/` (with the dev dependencies installed, same as for tests):

```bash
python -m benchmarks run
```

That generates the corpus, runs the full suite, prints a summary, and writes
results to `backend/benchmarks/results/<timestamp>-full-<commit>.json`
(git-ignored).

Useful variants:

```bash
python -m benchmarks run --profile smoke        # CI-sized harness check (~seconds)
python -m benchmarks run --profile quick        # small corpora, 2 iterations
python -m benchmarks run --filter detect        # only benchmarks matching a substring
python -m benchmarks run --iterations 5         # override the profile's iteration count
python -m benchmarks run --corpus-dir /tmp/c    # persist/reuse the generated corpus
python -m benchmarks run --no-memory            # skip the tracemalloc memory pass
python -m benchmarks list                       # list the full profile's benchmarks
python -m benchmarks corpus --output DIR        # generate the corpus only
```

## Comparing two commits

```bash
git checkout <base>   && cd backend && python -m benchmarks run --output /tmp/base.json
git checkout <change> && cd backend && python -m benchmarks run --output /tmp/new.json
python -m benchmarks compare /tmp/base.json /tmp/new.json
```

`compare` prints a Markdown report (use `--format json` for machines, and
`--output PATH` to write it to a file) and exits non-zero when it finds:

- **Regressions** — median wall time more than the threshold (default 10%,
  `--threshold`) slower than the baseline. Timings where both medians are
  under 10 ms are compared but never flagged; they are allocator/scheduler
  noise.
- **Counter drift** — a benchmark produced different logical results (e.g. a
  different findings count for the same corpus). This is a behavior change,
  never a performance win, and always fails.

Results are only comparable when their `corpus_version` matches; `compare`
refuses to diff across corpus versions.

### Regression policy

A change that makes any benchmark **more than 10% slower in the reference
environment** needs, in its PR, either:

1. an explanation of why the cost is justified (with the comparison report
   attached), or
2. an explicit baseline update agreed with a maintainer.

Timings from CI shared runners are too noisy to gate merges; CI only runs the
`smoke` profile plus the harness unit tests (`tests/test_benchmarks.py`) to
protect harness correctness. Full runs are local, scheduled, or manual.

## What is measured

| Group | Benchmarks | Notes |
|---|---|---|
| `ingestion` | Defender JSONL, EVTX-derived JSON, generic CSV, Linux auth.log, mixed ZIP | Full `ingest_file_sync` path into a fresh case per iteration |
| `normalization` | `normalize_defender_jsonl_*` (parse + normalize, no DB), `bulk_insert_events_*` (pre-normalized rows → `add_events_bulk` + FTS) | At three corpus sizes |
| `detection` | Rebuilds over benign / mixed / suspicious corpora | State reset to the pre-detection baseline before every iteration, exactly like a rebuild |
| `queries` | Timeline, FTS search, case statistics, entity graph build, finding serialization | One shared ingested+detected case; entity-graph cache cleared per iteration |
| `memory` | MemProcFS forensic-CSV artifact normalization | Synthetic `forensic/csv/` tree; no memory image required |

Frontend build-size and large-table render timings are planned but not yet
part of this suite; they will be tracked separately where reliably measurable.

## Corpus

Generated by `benchmarks/corpus.py`, versioned by `CORPUS_VERSION`, and
anchored to a fixed base time with seeded RNGs, so a given (version, size)
pair always produces **byte-identical files**. `manifest.json` records the
SHA-256, byte size, and row count of every file; `tests/test_benchmarks.py`
asserts determinism.

Sizes: `xs` (150 rows, smoke only), `small` (1,000), `medium` (5,000),
`large` (20,000) rows per file. Detection corpora come in three mixes:
`benign` (0% suspicious records), `mixed` (10%), `suspicious` (50%).

Content is synthetic: hosts like `WKS-ALPHA`, TEST-NET IPs (RFC 5737),
`.invalid` domains, and command lines chosen to exercise detection pattern
families without reproducing any real incident data.

**Bump `CORPUS_VERSION`** whenever a generator change alters produced bytes,
and expect to re-baseline afterwards.

## Result schema (`schema_version: 1`)

```jsonc
{
  "kind": "investigator-benchmark-results",
  "schema_version": 1,
  "created_at": "2026-01-05T08:00:00+00:00",
  "profile": "full",
  "corpus_version": "1.0.0",
  "environment": {
    "commit": "…", "commit_dirty": false,
    "platform": "…", "machine": "x86_64", "cpu_count": 8,
    "python_version": "3.11.9", "python_implementation": "CPython",
    "sqlalchemy_version": "2.0.51", "sqlite_version": "3.45.1"
  },
  "benchmarks": [
    {
      "name": "detect_rebuild_mixed_medium",
      "group": "detection",
      "corpus_size": "medium",
      "iterations": 3,
      "operations": 5000,                  // logical units processed
      "wall_seconds": [1.01, 0.99, 1.0],   // per timed iteration
      "wall_seconds_min": 0.99,
      "wall_seconds_median": 1.0,          // the compared statistic
      "wall_seconds_mean": 1.0,
      "ops_per_second": 5000.0,            // operations / median
      "peak_tracemalloc_bytes": 1048576,   // separate untimed pass; null with --no-memory
      "counters": {"findings": 40}         // scenario-specific correctness totals
    }
  ]
}
```

Measurement protocol, per benchmark: one untimed warmup (absorbs lazy imports
and cold caches), then N timed iterations (`gc.collect()` before each,
`time.perf_counter` around the operation), then one untimed pass under
`tracemalloc` for peak Python heap — tracemalloc overhead must never pollute
timings. Counters must be identical across iterations or the run fails: the
suite doubles as a determinism check.

## Adding a benchmark

Add a `BenchmarkSpec` in `backend/benchmarks/scenarios.py`. Rules:

- Exercise the real app code path; never fork parser/detector logic into the
  benchmark.
- `run()` returns `{"operations": N, ...counters}` and must be deterministic
  for a fixed corpus.
- Anything expensive that isn't the measured operation belongs in `setup`
  (once) or `prepare` (per iteration, untimed).
- Corpus changes require a `CORPUS_VERSION` bump.
